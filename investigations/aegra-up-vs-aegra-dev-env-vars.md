# Investigation: aegra up vs aegra dev environment variables

**Date:** 2026-04-06

## Summary

`aegra dev` runs the server directly on the host, so it inherits all shell environment variables. `aegra up` runs `docker compose up --build`, which puts the API server inside a Docker container. Docker containers do not inherit host environment variables unless explicitly passed through.

## The problem

`aegra up` uses the `docker-compose.yml` auto-generated by aegra. This file includes `env_file: .env`, but we don't use `.env` files (credentials in plain text). Without `.env` and without explicit passthrough, the container can't see env vars like `GITHUB_TOKEN`, `ANTHROPIC_API_KEY`, etc.

## Required docker-compose.yml changes for aegra up

Remove the `env_file` block and add these to the `environment:` section of the API service:

```yaml
      - GITHUB_TOKEN=${GITHUB_TOKEN}
      - TOKEN_ENCRYPTION_KEY=${TOKEN_ENCRYPTION_KEY}
      - ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY}
      - SANDBOX_TYPE=${SANDBOX_TYPE:-devpod}
      - DEVPOD_PROVIDER=${DEVPOD_PROVIDER:-docker}
      - LANGGRAPH_URL=http://localhost:${PORT:-2026}
```

The `${VAR}` syntax causes docker compose to read the value from the host shell at startup.

## Caveat

`docker-compose.yml` is auto-generated by aegra and listed in `.gitignore`. These changes will be lost if aegra regenerates the file. This would need to be addressed upstream (e.g., aegra supporting a compose override file or reading env var passthrough config).

## Recommendation

Use `aegra dev` for local development. It avoids this entire problem. Only pursue `aegra up` if you specifically need the full Redis broker stack running in containers.
